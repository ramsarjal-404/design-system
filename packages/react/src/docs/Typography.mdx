# Typography

Lepidus type is driven entirely by the token build. Each text role is a composite of
`--typography-<role>-fontSize`, `-lineHeight` and `-letterSpacing` tokens (generated from the
Figma DTCG export). The composite tokens carry **size, line-height and letter-spacing only** —
weight is applied per use from the `--font-weight-*` scale (e.g. Button pairs its role with
semibold). Every sample below renders live from the loaded `tokens.css`.

## Font stack

The single family token is `--font-family-primary`, resolving to
**'Open Sans', system-ui, sans-serif**. Open Sans is loaded by the host application; the
system-ui fallback keeps metrics close when it is unavailable. No secondary or monospace family
token exists in the build.

## Component roles

These roles are aliased into the component tier (e.g. `--component-button-fontSize` →
`--typography-button-fontSize`), so components never reference primitives directly.

## Usage guidance

- **heading-h1/h2** — one per page/section; page and section titles only. Don't skip levels for
  visual effect — pick the semantic level and adjust spacing instead.
- **heading-h3–h6** — subsection, card and panel titles in descending nesting order.
- **body-md (14px)** — the default UI text size. Reach for **body-lg** only for lead paragraphs
  or marketing-adjacent surfaces; reach for **body-sm** for helper/error text under fields and
  captions.
- **label-md/sm** — form-field and metadata labels, paired with semibold weight. (Note: Input
  labels render in gray `--color-text-primary` tones, not brand blue.)
- **button / nav / input / table-\* / modal-title / badge** — consume these via their
  `--component-*` aliases inside components; never restyle a component's text with a different
  role.
- Line-heights come from a four-step scale (`tight` 16 · `default` 19 · `relaxed` 22 ·
  `loose` 28 · `heading` 36) — always use the role's paired token rather than a unitless value.
