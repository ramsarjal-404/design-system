# Using Lepidus without React

`@lepidus/css` delivers the design system as **plain CSS classes** — for any
page or app written in HTML/CSS/JS, with no framework and no build tool.
It is generated from the same source as the React components, so the two can
never drift apart. Every example below is **live** — rendered by the plain CSS
in this very page — and respects the theme switcher in the toolbar.

## Setup

Link one stylesheet (from `packages/css/dist/`), then write HTML:

```html
<link rel="stylesheet" href="lepidus.css" />
```

Theming: set `data-theme` on the root element — `light` (default), `dark`, or `hc`.

```html
<html data-theme="dark">
```

Class naming is BEM with an `lp-` prefix: block (`lp-button`),
modifier (`lp-button--primary`), element (`lp-button__icon-left`).

```html
<button class="lp-button lp-button--primary lp-button--md">Primary</button>
<button class="lp-button lp-button--secondary lp-button--md">Secondary</button>
<button class="lp-button lp-button--danger lp-button--md">Danger</button>
```

Sizes: `--sm` (dense UI), `--md` (default), `--lg` (with icon). Icons go in
`lp-button__icon-left` / `lp-button__icon-right` spans. Add `lp-button--full-width`
to stretch.

## Input

<div style={{ display: 'flex', flexDirection: 'column', gap: 16, maxWidth: 480, marginBottom: 16 }}>
  <div className="lp-input">
    <div className="lp-input__row lp-input__row--label-top">
      <label className="lp-input__label" htmlFor="mdx-i1">Server name</label>
      <div className="lp-input__field">
        <input className="lp-input__input" id="mdx-i1" placeholder="e.g. LDSP-FS-01" />
      </div>
    </div>
    <div className="lp-input__message">The display name shown in reports.</div>
  </div>
  <div className="lp-input">
    <div className="lp-input__row lp-input__row--label-top">
      <label className="lp-input__label" htmlFor="mdx-i2">Email</label>
      <div className="lp-input__field lp-input__field--error">
        <input className="lp-input__input" id="mdx-i2" defaultValue="not-an-email" aria-invalid="true" />
      </div>
    </div>
    <div className="lp-input__message lp-input__message--error">Enter a valid email address.</div>
  </div>
</div>

```html
<div class="lp-input">
  <div class="lp-input__row lp-input__row--label-top">
    <label class="lp-input__label" for="email">Email</label>
    <div class="lp-input__field lp-input__field--error">
      <input class="lp-input__input" id="email" aria-invalid="true" aria-describedby="email-err" />
    </div>
  </div>
  <div class="lp-input__message lp-input__message--error" id="email-err">Enter a valid email address.</div>
</div>
```

Label position: `lp-input__row--label-top` or `--label-left` (fixed-width
label column; align the helper text under the field with
`lp-input__message--indent`). Field states: `lp-input__field--error`,
`lp-input__field--disabled` (also set `disabled` on the input itself).
Add `lp-input--full-width` to the wrapper to stretch.

## What's covered so far

Button, Badge, Tag, Card and Input ship today; the rest of the library is
being converted component by component. Components with built-in behavior
(Modal, Dropdown, Tabs, Toast) will arrive together with a small vanilla-JS
helper. The full one-page showcase lives at `packages/css/demo/index.html`.
