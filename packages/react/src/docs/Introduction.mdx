# Lepidus Design System

Lepidus is the component library for Lepide products: **38 React components**, fully driven by a
three-tier design-token pipeline generated from the Figma source of truth
([Lepidus on Figma](https://www.figma.com/design/Ck7BIRlRw2bwHRk8PL5IfC/Lepidus)).

## Token architecture

Every visual property in every component resolves through the same chain — no hardcoded values:

```
Primitive  ──▶  Semantic  ──▶  Component
--blue-600      --color-brand-primary      --component-button-primary-fill
#1c4599         var(--blue-600)            var(--color-brand-primary)
```

- **Primitive** — raw values: color scales (`--blue-*`, `--gray-*`, `--lightblue-*`…), spacing
  (`--space-*`), radii (`--radius-*`), font sizes/weights/line-heights.
- **Semantic** — intent-named aliases: `--color-text-primary`, `--color-border-brand`,
  `--color-button-disabled-bg`. These are what theming swaps (light / dark / high-contrast layers
  exist in the build).
- **Component** — per-component bindings: `--component-button-*`, `--component-dropdown-*`,
  `--component-toast-*`. Components consume *only* this tier (plus shared space/radius/typography),
  so a token edit in Figma propagates everywhere without touching component CSS.

Tokens are authored as DTCG JSON in `packages/tokens/src/`, exported from Figma, and built to CSS
custom properties with Style Dictionary:

```bash
npm run tokens        # → packages/tokens/build/css/tokens.css
```

The build currently emits **800+ declarations across 3 theme layers**.

**Primitives** — `Portal`, `FocusTrap`, `Popover` and `VisuallyHidden` in
`packages/react/src/primitives` are exported for app use (Tooltip and the overlay surfaces build
on them), but they are not themselves design-reviewed components: no Figma frame, no status
badge, no docs page of their own.

Each component's docs page includes: an **Overview** (when to use it and which sibling to prefer),
**Anatomy**, a **Design tokens** table mapping every visual part to its CSS variable and resolved
value, **States & variants** mapped to the Figma variants, **Accessibility** notes derived from the
implementation, and **Usage** do/don'ts.

## Conventions

- **Styling** — CSS Modules per component; every value is `var(--token, fallback)`. The fallback
  mirrors the token's resolved value so components degrade gracefully without the stylesheet.
- **API** — typed props in `ComponentName.types.ts`; `forwardRef` to the natural root element;
  native HTML attributes pass through.
- **Composition** — components reuse each other rather than re-implementing (e.g. Dropdown's
  Cancel/Apply footer renders the system `Button`).
- **No generic UI** — pickers and popovers are custom-built and token-bound; native OS menus
  (`<select>` lists, default spinners) are never shown.

## Choosing between similar components

- **Input vs TextField vs Textarea** — `Input` is the labeled form field with helper/error
  messaging (25px radius). `TextField` is the standalone label-less pill for quick entry
  (44px radius). `Textarea` is the multi-line description box (15px radius).
- **Message vs Toast** — interrupt with `Message` (role="alert", action buttons), notify with
  `Toast` (role="status", transient pill).
- **Badge vs Toast** — `Badge` is a static inline status label; `Toast` announces an event.

The full decision guide — interruption spectrum, selection cardinality, loading states and more —
lives in **Foundations → Choosing Components**.
